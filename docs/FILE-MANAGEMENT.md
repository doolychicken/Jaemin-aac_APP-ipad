# 파일 관리 기준

## 위치별 역할

| 종류 | 관리 위치 | 기준 |
| --- | --- | --- |
| 앱 실행 | 루트 HTML, `js/`, `css/`, `sw.js`, `manifest.webmanifest` | 파일명·저장 키 변경 시 기존 사용자 데이터와 캐시 검증 |
| 앱 이미지·소리·영상 | `images/`, `audio/`, `video/` | 실제 사용하는 최종본. 새 자료는 기능별 하위 폴더에 추가 |
| 제작·검사 코드 | `scripts/` | 재실행 가능한 도구만 보관 |
| 스티커 배치 원본 | `scripts/sticker_books/` | 생성된 JS보다 이 원본을 먼저 수정 |
| 설명·제작 기록 | `docs/`, `docs/sticker-books/` | 사용법과 변경 이유 기록 |
| 인쇄 제작 | `_local/print-projects/kitchen/`, `_local/print-projects/all-books/` | 원본 이미지에서 인쇄용 JPG 제작. 앱에 배포하지 않음 |
| 예전 이미지 제작물 | `_local/imagegen/` | 이전 PDF·이미지·제작 스크립트 보존 |
| 큰 영상 원본 | `_local/media-originals/` | 앱이 사용하는 `video/`의 최종 영상과 구분하여 보관 |
| 검토 사진 | `_local/review/bathroom/` | 이전 화장실 검토 화면 |
| 브라우저 검사 결과 | `_local/sticker-book/`, `_local/home-stickers/` 등 | 검사 프로그램이 생성하는 폴더 유지 |
| 도구·음성 제작 재료 | `_local/test-tools/`, `_local/print-tools/`, `_local/speech/` | 제작 스크립트가 참조하므로 임의 이동하지 않음 |
| 파일 현황·정리 이력 | `_local/management/` | 용량, 미등록 파일, 이동 전후 해시 기록 |
| 사용자가 출력할 파일 | 바탕화면 → 종류별 폴더 → `01_인쇄할 최신본` | 완성된 JPG만 사용. 앱용 이미지와 구분 |

## 새 자료를 추가할 때

1. 참고 사진과 생성 시안은 `_local/`의 해당 작업 폴더에 둡니다.
2. 앱에서 사용할 최종본만 `images/기능명/`에 넣습니다. 기존 파일을 지우거나 이름을 바꾸기 전에 참조를 확인합니다.
3. 화면 데이터와 오프라인 캐시를 함께 갱신합니다. 스티커는 기존 ID·진도 저장 키를 유지합니다.
4. 아래 점검 명령을 실행합니다. 화면 동작을 바꿨다면 브라우저 검사와 실제 아이패드 확인을 추가합니다.
5. 인쇄본은 앱 자료와 별도로 재생성합니다. 기존 최신본은 이전버전 폴더에 보관하고 새 JPG를 넣습니다.

## 정기 점검 명령

프로젝트 폴더에서 실행합니다. 어디서 실행하더라도 도구는 프로젝트 위치를 기준으로 작동합니다.

```powershell
python scripts/manage-project.py inventory
python scripts/manage-project.py check
python scripts/manage-project.py check --browser
```

`inventory`는 파일 수, 폴더 용량, 큰 미디어 파일, Git 미등록 파일, 누락된 추적 파일을 보고서로 저장합니다. 파일을 자동 삭제하거나 이동하지 않습니다. 미등록 파일은 미사용 파일과 다릅니다.

`check`는 스티커 배치, 오프라인 목록, 이미지 연결과 변경 파일 형식을 검사합니다. `--browser`를 붙이면 기존 앱·스티커북 브라우저 회귀 검사도 실행합니다. 실제 아이패드에서의 터치·소리 확인을 대신하지는 않습니다.

## 보관과 백업

`_local/`, `output/`, Python 임시 캐시는 Git에 포함하지 않습니다. Git 제외는 백업을 뜻하지 않습니다. 인쇄 제작 코드와 카탈로그가 있는 `_local/print-projects/`, 개인 참고 사진, 바탕화면 최신 인쇄본은 별도로 백업해야 합니다. 이미지 크기나 용량을 줄일 때는 원본 보관 후 화면·인쇄 품질을 확인합니다.

기존 앱 자료는 URL과 캐시에 연결되어 있으므로 한꺼번에 이동하지 않습니다. 파일이 늘어나면 먼저 현황 보고서로 대상을 확인하고 기능별로 나눠 정리합니다.
